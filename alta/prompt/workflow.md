## Ограничения сайтов
**Текущий сайт возьми из приглашения Хобота.** Здесь, ограничения, которые были замечены, список может пополняться.

### ai_url=https://arena.ai:
  - перетаскивать можно только PNG, JPEG, PDF; другие форматы (DOCX, XLSX) перетаскивать нельзя.
  - максимальный объем файлов - 15Мб
  - максимальный объем поля ввода чата для текстов (ответ Хобота) около 110Кб. Превышение = невозможность ответа;
  - объем вывода - не ограничен;

### ai_url=https://chat.z.ai, https://chat.qwen.ai:
  1) перетаскивать можно PNG, JPEG, PDF, DOCX, XLSX;

  2) При выводе объем блока кода ограничен 11Кб, превышение = потеря данных. Больше файлы выводи отдельными директивами.
     Используй write_file с параметром `append`.
 
  3) Для ускорения работы помещай несколько команд в одну директиву (с учетом ограничений).

  4) Ограничений на ввод нет.

### ai_url=https://chat.z.ai:

  2) При выводе в блок кода длина строки ограничена 1.5Кб. Превышение = потеря данных. Разбивай вывод на отдельные
     команды внутри директивы.

### https://chat.deepseek.com:
  - перетаскивать можно PNG, JPEG, PDF, DOCX, XLSX;
  - ограничений на ввод и вывод пока не замечено.

## 0. Этапы работы

## Этап 0.  Конвертация первички (Опционально)

AI подготавливает первичные документы к обработке: приводит docx, xlsx, pdf и образы к текстовому виду (md).
Если этап не выполнен, то этап 1.0 будет брать данные прямо из первички.

После завершения этапа напомнить оператору очистить историю / пересоздать чат.

Исходные данные:
- первичные документы `alta\source\<имя кейса>\...\<папка первичных документов>\` 
- промпт `alta\prompt\stage_0\doc_conversion_schema.md`
- промпт `alta\prompt\stage_0\doc_conversion_review_schema.md`

Результаты `alta\source\<имя кейса>\...\<папка первичных документов>\md\`
- `*.md` текстовые версии документов
- `DOC_CONVERSION_REVIEW.md` 

## Этап 1.0  Сбор и нормализация фактов
- Если этап 0 был выполнен, используй `alta\source\<имя кейса>\...\<папка первичных документов>\md\`. 
- Если md версий документов не существует или они содержат недостаточно данных, уведомить оператора и использовать первичку.

**Результаты в `alta\stage_1.0_result\<имя кейса>\`:**
- `primary.md` — нормализованная база фактов поставки (источник истины).
- `primary_review.md` — отчет по этапу, вопросы к оператору.

**Исходные данные:**
- `alta\source\<имя кейса>\...\<папка первичных документов>\` (первичка и/или md-версии из Stage 0)
- `alta\stable_source\` (не меняются между поставками):
  - *.xml, кодировка cp1251
  - stable_data, кодировка utf-8

**Промпты:** `alta\prompt\stage_1.0\primary_schema.md`, `primary_review_schema.md`.

**Результаты в `alta\stage_1.0_result\<имя кейса>\`:**
- `primary.md` — нормализованная база фактов поставки (источник истины).
- `primary_review.md` — отчет по этапу, вопросы к оператору.

## 1. Базовые правила

### 1.1. Никакой отсебятины

Любое значение, попадающее в `primary.md`, должно быть:
- извлечено из первичных документов;
- либо подтверждено оператором;
- либо корректно выведено из подтвержденных данных;
- либо явно помечено как эталонное наблюдение, не являющееся фактом новой поставки.
  Если данных не хватает — остановиться и обратиться к оператору либо явно зафиксировать пробел.
