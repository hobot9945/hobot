# СХЕМА doc_conversion_review.md
Описывает правила формирования doc_conversion_review.md. Примеры фрагментов разметки приводятся в fenced blocks 
(````review), но в сам doc_conversion_review.md fenced blocks не переносятся.

## Назначение
Фиксация результатов конвертации первички. Генерируется **один раз** после обработки всей пачки документов кейса.

## ВАЖНО: единица учета (детерминированно)
- Таблица в этом документе строится по результатам этапа 0.
- **1 строка таблицы = 1 md-файл** в папке `...\md\` (кроме самого `DOC_CONVERSION_REVIEW.md`).
- `всего документов` = количество таких md-файлов.
- Запрещены агрегации в стиле "счета", "платежки" и т.п., если на диске есть несколько md-файлов.
 
````review
## 1. Метаданные
- `название кейса`: <кейс>
- `путь к папке поставки`: <путь>
- `дата выполнения`: <YYYY-MM-DD>
- `платформа`: <ai_url>
- `всего документов`: <N>

## 2. Таблица обработки документов
| NN | Документ | Статус | Качество | Доработка | Лог конвертации | Исходный файл | md-файл |
|----|----------|--------|---------------|-----------|-----------------|--------------|--------|
| 1  | контракт | confirmed | high | - | PDF → JPEG @100 | SALES CONTRACT NoLM-2553.pdf | SALES CONTRACT NoLM-2553.md |
| 2  | счет на оплату | confirmed | high | - | PDF → JPEG @100; 1 стр. | Счет_№..._от_14-01-2026.pdf | Счет_№..._от_14-01-2026.md |
| 3  | счет на оплату | pending | mid | требуется | PDF → JPEG @100; стр.1 mid | Счет_№..._от_27-01-2026.pdf | Счет_№..._от_27-01-2026.md |

## Решено оператором
- Вопросы, решенные оператором и занесенные в `operator_provided_data.md`.
````

**Детерминированные правила заполнения:**
- `Документ`: краткое назначение по содержанию (контракт, инвойс, упаковочный лист, СМР, платёжка, техописание и т.д.).
- `Статус`: `confirmed` (все ключевые поля `high`) / `pending` (есть `mid/low` по ключевым или `[OPERATOR_NEEDED]`).
- `Качество`: нижняя оценка распознавания страниц (`high`/`mid`/`low`).
- `Доработка`: нужна ли / требуется ли / возможна ли.
- `Лог конвертации`: краткая история фоллбэков (`—` если не применялись).
- `Лог конвертации`: короткая фиксированная история:
  - базовый случай: `PDF → JPEG @100`
  - если 1 страница: добавить `; 1 стр.`
  - если были ретраи: `; ретрай @150 стр.<N>`
  - если без конвертации (например, текстовый исходник): `direct (txt/md/xml)`
- `md-файл`: имя файла в `...\md\` (как на диске), соответствующий этой строке.
- `Исходный файл`: брать из строки `META: полное путевое имя исходного файла` внутри этого md (в таблице указывать 
  только имя файла).
- `Документ`: тип документа по содержанию/`типовое имя` из META 
  (контракт/инвойс/упаковочный/ТД/СМР/ДО/счет/платежка/техописание/...).
- **Запрещены** маски (`*`) и диапазоны в `Исходный файл`.

````review
## 3. Незакрытые вопросы
- Перечисляй только документы/поля со статусом `pending` или `[OPERATOR_NEEDED]`.
- Указывай конкретный документ, поле, причину и что требуется от оператора.
- Формат записи:
  ```
  - <Имя файла>, <Заголовок блока (ID)>: <причина>. Требуется: <действие>.
  ```

## 4. Итоговая статистика
- `confirmed`: X
- `pending`: Y
- `total_audit`: N из M, % - общее покрытие по всем документам.
- `Доработка`: нужна ли / требуется ли / возможна ли.
- `Нужна ли помощь оператора`: да / нет.

## 5. Оценка качества распознавания
Оцени по пятибальной шкале.
````
## Чек консистентности
- `всего документов` = числу строк таблицы.
- `confirmed + pending` = числу строк таблицы.
- Если `pending = 0` ⇒ раздел "Незакрытые вопросы" должен содержать `- Нет.`

## Условие завершения этапа
- Если обработаны все доступные первичные документы, и
- если качество всех документов `high` или
- для документов `low|mid` использованы все формы обработки, описанные в `doc_conversion_schema.md`, п. 1.7 `extraction_order`.

## Сообщи результаты оператору
Если остались незакрытые вопросы / pending, **AI обязан уведомить оператора**.
