# ИНСТРУКЦИЯ: Этап 0 — Конвертация первичных документов

## 0. СПИСОК НЕОБХОДИМЫХ ПЕРВИЧНЫХ ДОКУМЕНТОВ

1. **Инвойс (Invoice)** — коммерческий счет на оплату товара.
2. **Упаковочный лист (Packing List)** — сведения об упаковке, весах и местах.
3. Транспортный документ для автоперевозок, в зависимости от типа поставки:
  - Международная товарно-транспортная накладная (CMR) - автотранспорт
  - Авианакладная - авиаперевозка
  - Ж/д накладная - железнодорожная перевозка
  - коносамент - морской транспорт
4. **Платежное поручение (Payment Order)** — подтверждение оплаты товара (валютный перевод).
5. **Счет за перевозку (Service Invoice)** — счет от транспортной компании/экспедитора.
6. **Счет за страховку (Insurance Invoice)** — счет на оплату страховой премии.
7. **Техническое описание (TechDescription)** — технические характеристики, каталоги, чертежи товаров.
8. **Отчет СВХ (Storage Report / ДО-1 / ДО-2)** — отчет о принятии товаров на склад временного хранения (отсутствует
   в случае авиаперевозки).
9. **Добавочный лист к отчету СВХ (Storage Report Additional Sheet)** — добавочный лист к ДО-1/ДО-2.
10. **Транзитная декларация (Transit Declaration)** — документ, по которому груз шел под таможенным транзитом.

## 1. Формат md-файла

1) Заголовок документа:
```
# <Название документа> (например, ДОГОВОР КУПЛИ-ПРОДАЖИ LM-2553)
```

2) META:
```
## META:
  - типовое имя (Контракт, Инвойс и т.д.)
  - полное путевое имя исходного файла
```

3) Текст документа.
```
## Текст документа

### <Page N>
<текст N-й страницы>
### page_N_quality: <high|mid|low>
```

4) Список извлеченных смысловых блоков. Смысловые блоки извлекаются в порядке следования в шаблоне. Номера блоков
   начинаются с 1 и увеличиваются на 1.
```
## Смысловые блоки:
| NN  | наименование блока   | value      | quality        |
|-----|----------------------|------------|----------------|
| <n> | <наименование блока> | <значение> | <low|mid|high> |
```
где NN - номер поля в шаблоне,
наименование блока - название поля в шаблоне.

Массивы оформляются отдельными таблицами. При разрыве таблиц выводи заголовок, иначе формат ломается.

5) Список плохо читаемых смысловых блоков. Блоки, которые прочлись с качеством `low|mid` (если есть), должны
   быть здесь перечислены.
```
## `unreliable_semantic_blocs`:
| Page | NN   | Наименование блока   | value      | quality        | note  |
|------|------|----------------------|------------|----------------|-------|
| <N>  | <NN> | <наименование блока> | <значение> | <low|mid|high> | <...> |
```

6) Итог: В конец каждого `.md` добавь обязательный блок:
```
## Итог:
  <из какого формата принят текст, был ли факт промежуточного преобразования PDF → JPEG с подробностями (число страниц, DPI)>

  document_quality: <high|mid|low> (нижнее качество среди страниц/блоков)
```

## 2. Правила извлечения данных и генерации

### 2.0 Главная задача:
- **Цель:** распознать текст первичных документов и перевести документы в Markdown, обеспечивая:
    - полное(дословное) распознавание текста и перенос его в раздел `Текст документа`;
    - постраничная оценка качества распознавания;
    - извлечение смысловых блоков согласно шаблонам; 
    - оценка качества извлечения смысловых блоков.
  
- **ИЗОЛЯЦИЯ:** документы **НЕЗАВИСИМЫ** друг от друга. Обрабатывай каждый документ отдельно, не отвлекайся на анализ
  содержания остальных. **ЗАПРЕЩЕНО** переносить данные между документами.

### 2.1 ТРЕБОВАНИЯ К КАЧЕСТВУ
- **!!!ПОЛНОЕ И ТОЧНОЕ ИЗВЛЕЧЕНИЕ ТЕКСТА ПЕРВИЧНЫХ ДОКУМЕНТОВ ИМЕЕТ АБСОЛЮТНУЮ ВАЖНОСТЬ ДЛЯ ВСЕЙ ПОСЛЕДУЮЩЕЙ ОБРАБОТКИ!!!**
  Исключение - если есть выбор между русским и английским (китайским) вариантом текста документа, извлекается только 
  русский вариант.

- **ЗАПРЕЩЕНО ВЫДУМЫВАТЬ ДАННЫЕ. В ЦЕЛЕВОМ ФАЙЛЕ МОГУТ ПРИСУТСТВОВАТЬ ТОЛЬКО ДАННЫЕ ИЗ ИСХОДНОГО ФАЙЛА.**

- **ЗАПРЕЩЕНО ЗАМЕНЯТЬ ТЕКСТ ДОКУМЕНТА ПЛЕЙСХОЛДЕРАМИ**. AI, используя **ВНУТРЕННЕЕ РАСПОЗНАВАНИЕ**, извлекает текст и
  помещает его в md-файл.

- Большой объем текста **НЕ СЛУЖИТ ПРИЧИНОЙ СОКРАЩЕНИЙ**

- Текст документа и смысловые блоки — разные сущности. Текст документа выводится дословно и полностью, без изменений. 
  Смысловые блоки — это только средство концентрации внимания на ключевых элементах документа. 
  Они **НЕ ОТМЕНЯЮТ И НЕ ОСЛАБЛЯЮТ,** а наоборот, **УСИЛИВАЮТ** требования к полноте извлекаемого текста. Смысловая
  единица, зафиксированная в смысловом блоке **ОБЯЗАНА ОСТАТЬСЯ В РАЗДЕЛЕ ТЕКСТА ДОКУМЕНТА!**

### 2.2 Размещение входных и выходных файлов
- **Вход:** `alta\source\<ИмяКейса>\<номер_поставки>\<папка первичных документов>\` (первичка: PDF, DOCX, XLSX, PNG, JPEG).
- **Выход:**
    - `alta\source\<ИмяКейса>\<номер_поставки>\<папка первичных документов>\md\*.md` (md-версии документов) + `DOC_CONVERSION_REVIEW.md`.
    - `alta\source\<ИмяКейса><номер_поставки>\<папка первичных документов>\DOC_CONVERSION_REVIEW.md`.

где <папка первичных документов> - это корневая папка первички. В ней могут присутствовать подпапки с первичными документами.

**Запрещено** читать файлы каталога `operator`, они НЕ являются исходными данными.

### 2.3 Общие правила извлечения данных
При формировании раздела "Текст документа" md-файла **АI ОБЯЗАН ИЗВЛЕЧЬ ПОЛНЫЙ (ДОСЛОВНЫЙ) ТЕКСТ ДОКУМЕНТА:**
 
  - Сохраняй текст в md-файле максимально точно, без пересказа, урезаний сокращений, выжимок, агрегации. 
    Таблицы в исходном документе переноси в раздел "Текст документа" как есть, в виде таблиц. Исключение - 
    `### 2.4 Упрощенное форматирование текста документа`.

  - **НЕДОПУСТИМО**, принимая данные, отбрасывать их наименования. Например: "683.00" вместо "Price: $683.00" - 
    потеря смысла.

  - Извлекай данные как есть. Опечатки оригинала сохраняй. Недостающее не додумывай.

  - **БОЛЬШОЙ ОБЪЕМ ДАННЫХ НЕ СЛУЖИТ ПРИЧИНОЙ УРЕЗАНИЙ/СОКРАШЕНИЙ!!!**

  - Вставляй строку с оценкой уверенности распознавания **ПОСЛЕ КАЖДОЙ СТРАНИЦЫ/БЛОКА**: `page_quality: <high|mid|low>`.

  - **Классификация по содержанию:** Имя файла — не источник истины. Определяй тип документа по структуре и реквизитам. 

  - **Отбрасывай мусор** - исключением из требования полного извлечения данных является пропуск мусорных файлов: 
    - Не принимай файлы, которые однозначно не имеют отношения к ДТ / формализации ДТ документов. 
    - Если файл пропущен как не относящийся к ДТ — в ревью обязательна отдельная строка со статусом `skipped`.

### 2.4 Упрощенное форматирование текста документа
Если в шаблоне есть запрос на упрощенное форматирование, и **ТОЛЬКО В ЭТОМ СЛУЧАЕ**, при формировании раздела 
`## Текст документа`, AI ОБЯЗАН:
  - Представить данные строго в текстовой форме, без включения форматирующих символов. Например, воздержаться от 
    формирования md-таблиц.
  - Проверить, что приняты ключевые данные. Например, `Insurance Invoice` **ГАРАНТИРОВАННО ДОЛЖЕН СОДЕРЖАТЬ:
    - валюту платежа,
    - сумму,
    - назначение,
    - стороны,
    - реквизиты,
    - подписи.

### 2.5 `file_repare_strategy` (патч vs полная перегенерация)
  - Если правки затрагивают <50% строк файла → применяй патч.
  - Если >50% или структура кардинально изменилась → перегенерируй файл полностью.

### 2.6 Разные форматы одного документа
Файлы с одним базовым именем представляют один документ:
  - <basename>.<txt|xml|docx|xlsx|pdf>;
Исключение - конвертация многостраничного PDF-файла в образы. Тогда к базовому имени добавляется номер страницы:
  - <basename_N>.<png, jpg>, где N - номер страницы документа.

### 2.7 Именование md-файлов

  - Если исходный файл содержит один документ: имя md-файла = <basename>.md.

  - Если файл содержит больше одного документа (каждый соответствует своему шаблону), AI обязан сгенерировать для каждого
    шаблона отдельный md-файл. Имя md-файла = <basename>_<тип_документа>.md, где <тип_документа> (например, Invoice, 
    PackingList).

  - Если для однотипных документов возникает неоднозначность, она разрешается добавлением номеров (например, Invoice_1,
    Invoice_2, ...)

### 2.8 `get_file_tools` (средства чтения файлов) 
Использование powershell для доступа к файлам часто приводит к ошибкам кодировки. Где возможно, используй:
  - TXT, MD - `read_file`, utf-8;
  - XML - `read_file`, cp1251;
  - XLSX, DOCX, JPEG, PNG, TIFF, PDF - `drag_file_from_explorer_to_ai` - аналог подгрузки (upload) файла. После подгрузки,
    файл становится доступен AI и **ДОЛЖЕН БЫТЬ РАСПОЗНАН ЕГО ВНУТРЕННИМИ СРЕДСТВАМИ**. OCR сайта работают плохо, им 
    доверять нельзя. Если AI не получает доступа к файлу, он **ОБЯЗАН ОБРАТИТЬСЯ К ОПЕРАТОРУ.**
  - PDF может быть конвертирован в формат JPEG, постраничная конвертация. Конвертируется либо все страницы, 
    либо выбранная страница. Возможно задавать DPI, см. раздел `Инструмент pdftojpeg.bat`.
При перетаскивании файлов не полагайся на текстовый отчет, проверь что файл реально получен. Если нет - повтори. Потом 
обратись к оператору.

Выходные файлы:
  - Имена `.md` файлов строго соответствуют имени исходных файлов без расширения.

### 2.9 `retry_condition` (требование повторной попытки извлечения данных)
Выстави оценку уверенности распознавания каждой страницы/смыслового блока `<high|mid|low>`. Если хотя бы одна 
страница/блок распознаны с качеством `mid|low`, AI обязан выполнить extraction_order (п. 2.10). Исключений нет.

Рукопись/печати не распознаем, достаточно "(Подписи/печати присутствуют.)"
**Шкала уверенности:**
  - `high`: текст чёткий, структура ясна, расхождений с образом нет.
  - `mid`: есть сомнения (размыто, сложный шрифт, склеенные ячейки), но данные читаемы.
  - `low`: критические сомнения (артефакты, пропуски, неоднозначность).

### 2.10 `extraction_order` (порядок извлечения)
**ИМПЕРАТИВ: ЗАПРЕШЕНО ПРЕЖДЕВРЕМЕННО ПРЕКРАЩАТЬ ОБРАБОТКУ ФАЙЛА, ЕСЛИ ПРИСУТСТВУЕТ `retry_condition`.**

Обозначение `(PDF → JPEG)`:
 1) конвертация PDF → JPEG с DPI=100, все страницы;
 2) если остались страницы, распознанные с качеством `mid|low`, переходи к постраничной конвертации PDF → JPEG с 
    DPI=150;
 3) Если качество всё ещё не high — повторить с DPI=200.

Приоритет обработки форматов документов, в зависимости от платформы:
  1) Общее предпочтение форматов: PNG, JPEG → DOCX → XLSX → PDF → (PDF → JPEG). 

  2) arena.ai: (PDF → JPEG)

  3) qwen.ai, z.ai: (PDF → JPEG) → DOCX → XLSX

  - Если после всех попыток качество остаётся mid/low — зафиксировать это в unreliable_semantic_blocs и в Итоге с 
    указанием причины. Переходи к следующему документу.  

### 2.11 🛠 Инструмент pdftojpeg.bat - правила преобразования PDF → JPEG
Позволяет преобразовать PDF-файлы в JPEG формат с заданным DPI. Либо все страницы PDF → группа файлов JPEG, 
либо заданная страница PDF → файл JPEG. 

**Путь:** `alta\service\script\pdftojpeg.bat`  
**Запускать из корня проекта:** `C:\...\hobot\`  
**Синтаксис:** `pdftojpeg.bat "полный_путь_к.pdf" <DPI> [номер_страницы]`

**Параметры:**
- `<DPI>`: обязательный. `100` → первая попытка, `150` → вторая попытка.
- `[номер_страницы]`: опциональный. Если указан, извлекается только эта страница. Если опущен - все страницы.

**Выход:** 
  - `alta\work\<имя_pdf>_<номер>.jpg` (нумерация с 1),
  - имя файла / файлов помещается в отчет, отдельная проверка наличия / имен файлов НЕ требуется. 
  - Скрипт сам удаляет старые файлы с этим префиксом перед запуском.

**Правила применения:**
- Всегда указывай номер проблемной страницы (3-й параметр), чтобы не генерировать лишние файлы.
- После генерации сразу загружай полученные JPEG в чат через `drag_file_from_explorer_to_ai` и перечитывай блок.
- Если после 150 DPI уверенность всё ещё не `high` → ставь `[OPERATOR_NEEDED]` и переходи к следующему документу.

## 2.12 Правила оформления таблиц
Скрипт `gen_result_fields_audit.bat` проверяет правильность оформления **ВСЕХ** таблиц. Ниже приведены обязательные 
требования, которые действуют для любой таблицы (включая таблицу смысловых блоков, unreliable_semantic_blocs, массивы, 
и любые другие).

1. **Пустая строка перед таблицей:** Перед строкой заголовка любой таблицы ВСЕГДА должна стоять пустая строка.

2. **Порядковые номера в первой колонке:** В любой таблице первая колонка должна содержать порядковые номера строк 
   (двузначные, 1-based: 01, 02, 03, ...). Смысловые колонки идут **ПОСЛЕ** колонки номеров строк.
   
3. **Перенос таблиц на новые страницы:** Если таблица в тексте документа переносится на следующую страницу, каждая часть 
   на новой странице оформляется как отдельная таблица:
  - Начинается с пустой строки и заголовка.
  - Нумерация строк в первой колонке на новой странице начинается заново с `01`.
  - Каждая часть закрывается своим маркером `_audit: n`.

4. Запрещено использовать пустые строки внутри таблицы, за исключением случаев, описанных в п. 3 (перенос таблиц на 
   новые страницы). Пустая строка считается завершением таблицы. Для следующей таблицы будет ожидаться строка заголовка.

5. **Обязательное закрытие маркером `_audit`:** Каждая таблица должна быть закрыта технической строкой `_audit: n` 
   на отдельной строке, где `n`:
  - для таблицы смысловых блоков `n` **БЕРЕТСЯ ИЗ ШАБЛОНА** (например, для инвойса _audit: 39);
  - для всех остальных таблиц - это номер последней строки данных в этой таблице (без лидирующих нулей).
    - Пример: если в таблице 13 строк, сразу под ней (без пустой строки) пишется `_audit: 13`.

### 2.13 Эффективность
- Многофайловые документы, например группу JPEG, как результат конвертации PDF, загружай, по возможности, одной директивой.
- Запись и проверку записи выполняй в одной директиве.

## 3. АЛГОРИТМ

### 3.0 Подготовка

Формирование директивы Хобота можно прерывать вплоть до вывода закрывающего тега `>>>ai dir_num dir_id`. Хобот игнорирует
незавершенные директивы.

**Правило `do_retry`:** если в процессе генерации документа (вывода в чат директивы Хобота) обнаруживается 
условие `retry_condition` и не исчерпан `extraction_order`, прерви формирование директивы Хобота и перейди к загрузке 
документа (раздел 3.1, п.1).

**Правило `do_retry_without_load`:** Если в ходе вывода директивы Хобота обнаружена ошибка, но `extraction_order` исчерпан,
прерви формирование директивы и начни заново БЕЗ загрузки документа (раздел 3.1.1).

md-файлы записывай с помощью write_file, patch_file в кодировке utf-8, **не используй unicode escape sequence**.

#### 3.0.0 Очистка мусора
Для очистки каталога `alta\work\` запусти скрипт `alta\service\script\cleanup_work.bat`.

#### 3.0.1 Разведка

  - пройди рекурсивно `alta\source\<ИмяКейса>\<номер_поставки>\` **с чтением размеров файлов**;
  - проверь, существует ли выходной каталог `md`;
  - учти раздел `## 0. СПИСОК НЕОБХОДИМЫХ ПЕРВИЧНЫХ ДОКУМЕНТОВ ПОСТАВКИ`;
  - согласуй с оператором набор обрабатываемых документов - запроси недостающие, запроси подтверждение на обработку
    сомнительных/вызывающих какие-либо вопросы документов;
  - покажи в чате список подлежащих обработке документов.

#### 3.0.2 Сканирование:

  - При наличии файлов с одинаковыми именами и разными расширениями бери приоритетный по удобству чтения, 
    см. `extraction_order`. 
  - Если сайт некачественно исполняет OCR для `PDF` (см. ограничения сайтов, например arena, deepseek), то
    пропусти шаг обработки PDF и сразу переходи к конвертированию `PDF` в `JPEG`.

#### 3.0.3 Выбор инкрементальная/полная генерация md-файлов 
  - Если каталог `md` не существует / пустой, нужна полная генерация,
  - иначе, сравни фактический состав md-файлов с их перечнем в `DOC_CONVERSION_REVIEW.md`, исправь его при необходимости.
    Обрабатывай документы, которые не обработаны/плохо обработаны (см. retry_condition).

### 3.1 **ДЕТЕРМИНИРОВАННО (СТРОГО ПО ПУНКТАМ).**
Вспомни ограничения сайта (см. workflow.md). **ОБРАТИ ОСОБОЕ ВНИМАНИЕ НА ОГРАНИЧЕНИЕ РАЗМЕРА ВВОДА (если есть)**.

**СТРОГО СОБЛЮДАЙ ПРАВИЛА ОФОРМЛЕНИЯ ТАБЛИЦ** (см. `п. 2.12`). При нарушении любого правила скрип завернет тебя назад.

Определи список документов. Обрабатывай документы в цикле по одному. Для каждого документа выполняй последовательно 
3 фазы: Распознавание, Извлечение, Запись.

#### 3.1.1 Фаза 1: Распознавание
Цель: получить стабильный текст документа с максимальным качеством.

  1) Загрузи документ в чат (`drag_file_from_explorer_to_ai`).
   
  2) Оцени качество распознавания каждой страницы по шкале <high|mid|low> (см. `retry_condition`).

  3) Цикл повторных загрузок: Если есть страницы с качеством mid|low и `extraction_order` не исчерпан:
   - Прервись.
   - Выполни следующее действие из extraction_order (например, конвертация PDF в JPEG с большим DPI).
   - Загрузи результат в чат.
   - Перейди к шагу 2.

  4) Если extraction_order исчерпан, а качество осталось mid|low, зафиксируй это и переходи к Фазе 2 
     (без дальнейших попыток).

#### 3.1.2 Фаза 2: Извлечение (Формирование md-файла)
Цель: сформировать содержимое md-файла строго по структуре из `## 1. Формат md-файла`.

##### 3.1.2.1 Заголовок и META
  - Сформируй заголовок документа # <Название документа>.
  - Сформируй блок ## META: с типовым именем и полным путевым именем исходного файла.

##### 3.1.2.2 Извлечение страниц
Иди строго по страницам первичного документа. **ДЛЯ КАЖДОЙ СТРАНИЦЫ:**
 
  1) Извлеки текст полностью, дословно, без сокращений и пересказа. 

  2) Если есть русский и английский/китайский варианты, извлеки только русский вариант, если это возможно без потери 
     данных отбросить. Иначе, оставляй все варианты.

  3) Оформи страницу: ### <Page N>, текст, ### page_N_quality: <high|mid|low>, см. `## 1. Формат md-файла`. 

##### 3.1.2.3 Извлечение смысловых блоков
Иди строго по полям шаблона документа, см. `## 4. Шаблоны формализуемых документов`. 
**ДЛЯ КАЖДОГО ПОЛЯ ШАБЛОНА (01, 02, ... N):**

  1) Найди соответствующий смысловой блок в распознанном тексте.

  2) Если блок ДОСТОВЕРНО отсутствует в документе, установи:
   - `value: ОТСУТСТВУЕТ`
   - `quality: high`

  3) Если блок распознан с качеством low|mid и фаза 1 исчерпана: запиши value как есть, quality: <low|mid>. Иначе, 
     возвращайся к п. 3.1.1.

  4) ЗАПРЕЩЕНО ОПУСКАТЬ ПОЛЯ ШАБЛОНА. Все поля от 01 до _audit обязаны попасть в таблицу.

  5) **ЗАПРЕЩЕНО ВЫДУМЫВАТЬ СМЫСЛОВЫЕ БЛОКИ, КОТОРЫХ НЕТ В ШАБЛОНЕ.** В частности, запрещено создавать массив, например, 
     массив товаров, если он не описан в шаблоне.

  6) Оформи таблицу смысловых блоков по правилам п. 2.12. Закрой её строкой _audit: N (из шаблона).

  7) Если документ содержит массив, описанный в шаблоне (например, товарные позиции в инвойсе), то:
    - извлекаются все элементы массива, которые присутствуют в документе, в исходном порядке;
    - массив нельзя заменять ссылкой, вроде, “см. текст документа”;
    - если качество для любого поля любого элемента массива `low|mid`, то `do_retry`/`do_retry_without_load`.

##### 3.1.2.4: Ненадежные блоки и Итог

  1) Сформируй таблицу ## unreliable_semantic_blocs: для блоков с качеством low|mid (если есть).
   
  2) Сформируй блок ## Итог: с описанием формата, конвертаций и document_quality.

#### 3.1.3 Фаза 3: Запись и валидация
Вспомни ограничения сайта (см. workflow.md). **ОБРАТИ ОСОБОЕ ВНИМАНИЕ НА ОГРАНИЧЕНИЕ РАЗМЕРА ВЫВОДА (если есть)**. 
Превышение размера вывода, как правило, выливается в сообщение Хобота о нарушении формата JSON (поскольку, вывод 
прерывается неожиданно).

  1) Сформируй директиву Хобота для записи md-файла (write_file/patch_file) в каталог md. 

  2) В той же директиве запусти `alta\service\script\gen_result_fields_audit.bat <путь>`.
   
  3) Если скрипт находит ошибки, исправь (см. `file_repare_strategy`) и повторяй аудит, пока файл не пройдёт проверку.

  4) Переходи к следующему документу.

### 3.2 Завершение обработки первичных документов

  4) Создай/обнови `DOC_CONVERSION_REVIEW.md`.

  5) **!!!КРИТИЧЕСКИЕ ТОЧКИ!!!** Следующие нарушения выливаются в **ЗАДЕРЖКИ ПОСТАВОК ПОКУПАТЕЛЮ/СУДЕБНОЕ ПРЕСЛЕДОВАНИЕ

## 4. Шаблоны формализуемых документов
Шаблон описывает смысловые блоки документа, которые необходимы для составления ДТ. 

1. **Таблица «Смысловые блоки»:**
    - Строится строго по полям шаблона.
    - Первая колонка (`NN`) содержит номера полей от `01` до конца шаблона.
    - Таблица обязательно закрывается строкой `_audit: N` (где N — общее число полей, берется из шаблона. Например,
      `_audit: 39` для Инвойса. Скрипт `alta\service\script\gen_result_fields_audit.bat <путевое_имя_md_файла>`
      проверит, что номера блоков возрастают на 1 и номер последнего блока равен N.

2. **Массивы не контролируются с помощью полей аудита.** Таблицы массивов завершаются техническими строками `_audit: M`, 
   где М - номер последней строки таблицы.
